## 架构总览

控制面高可用由三层各自独立的机制叠加，任何一层失效不等于其他层失效：

```
                  浏览器 / kubectl
                        |
                        |  https://192.168.80.100:8443
                        v
        [ 入口层 ]  keepalived VRRP  -> VIP 192.168.80.100
                        |  (三台 master 竞选，priority 200/150/100)
                        v
        [ 流量层 ]  haproxy :8443  ->  三台 apiserver :6443
                        |  (roundrobin + check，故障后端自动摘除)
                        v
        [ 状态层 ]  etcd 堆叠三成员（每台 master 一个，quorum = 2）
                        |
        +---------------+---------------+
        v               v               v
     master1 .20     master2 .21     master3 .22     worker1 .10   worker2 .11
     (2vCPU/3GB)     (2vCPU/3GB)     (2vCPU/3GB)     (2vCPU/3GB)   (1vCPU/2GB)
                                                          |
                                                  MySQL 主从 + local-path PV
```

数据面与控制面的三条独立链路：

- **集群控制链路**：kubectl → VIP:8443 → haproxy → apiserver → etcd。VIP 漂移归 keepalived，后端摘除归 haproxy，成员一致性归 etcd Raft，三者互不代理。
- **业务声明链路**：Git 仓库（master1 裸仓 + SSH）→ ArgoCD Application → `gitops-lab` 命名空间渲染对象；Helm 负责把 chart 渲染成清单，ArgoCD 负责持续对齐期望状态。
- **观测数据链路**：exporter 在各自端口暴露文本指标 → Prometheus 每 15s 主动拉取并写入 TSDB → Grafana 只读查询绘图。Grafana 查 Prometheus 走集群内 Service DNS，不经过任何对外入口。

## 全局约束（不可改参数）

- `--control-plane-endpoint=192.168.80.100:8443`：端口是 **8443 不是 6443**，该地址已固化进证书 SAN；事后改端口必须重签证书。
- `--pod-network-cidr=10.244.0.0/16`：不可使用 `192.168.0.0/16` 一类网段，会把节点网段整个包进去，导致路由错乱。
- VMware NAT 网关必须是 `.2`。填 `.1` 时内网 ARP 可通、出网全丢且不回 ICMP 错误，属高隐蔽性故障。
- containerd 2.x 的 `hosts.toml` 必须写成 `[host."https://..."]` 分节 + 换行 `capabilities = ["pull","resolve"]`。单行点号内联写法 TOML 语法合法但 containerd 解析不出，且**静默直连原站不报错**。
- `ctr` 与 `crictl` 不在同一命名空间：镜像导入导出必须带 `-n k8s.io`，否则 kubelet 看不见。
- `crictl pull` 验证必须用原生完整地址（如 `docker.io/library/busybox:1.36`），用短名会绕过 mirror 配置，验不出真实生效情况。
- 防火墙按标准姿势放行端口（`6443 8443 2379-2380 10250-10259 179 30000-32767` + 协议 `ipip`、`vrrp`）；Calico 默认 IPIP 而非 VXLAN，需放的是协议号而非 4789/udp。若环境已 `systemctl disable --now firewalld`，放行命令报 `FirewallD is not running` 属预期，端口清单仍应保留在配置资产中。
- VM 挂起会冻结时钟，恢复后需 `chrony makestep 1.0 -1` 强制对齐，否则证书校验与 etcd 时序判据失真。

## 镜像来源格局（重要约束）

部署期间镜像可达性发生过变化，复现时需按实际网络选择路径：

- K8s 组件 / pause / etcd 走 `k8s.m.daocloud.io`，docker.io 类走 `docker.m.daocloud.io`，配置在 `/etc/containerd/certs.d/docker.io/hosts.toml`。
- 后期实测：daocloud 的 blob 存储（Cloudflare R2 系）、quay.io、docker.io、ghcr.io 从 VM 均不可达；**仅 `registry.cn-hangzhou.aliyuncs.com` 可直拉**（`google_containers/*` 为 K8s 官方镜像同步）。
- 兜底路径：在可出网的宿主机按 registry v2 协议代拉并打成 docker-archive → SFTP 推入 VM → `ctr -n k8s.io images import`。内网节点间分发用 `ctr -n k8s.io images export/import/tag`，实测约 50 MB/s。
- 离线分发需要留意 `imagePullPolicy`：离线环境里 `Always` 会强制联网报到，即使本地已有该镜像也会 `ImagePullBackOff`。
