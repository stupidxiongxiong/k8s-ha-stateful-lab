# 02 主机底座与容器运行时

> 前置：`01-架构与环境快照.md`。本阶段在集群创建之前，作用于每一台 VM 的操作系统层。

## 范围

Rocky Linux 10 最小化安装后的主机配置：网络标识、内核与时钟、防火墙、容器运行时与 CRI 工具链、镜像加速与离线分发通道。此阶段不产生任何 Kubernetes 对象。

## 架构与数据流

```
kubelet ── CRI ──> containerd ──> runc ──> pause 沙箱 ──> 业务容器
                        │
                        └── certs.d/<registry>/hosts.toml
                                  │  (mirror 分节 + capabilities)
                                  v
                        可达镜像源 / 离线 import 的本地镜像
```

- containerd 2.4.x 自带 runc；Rocky 10 官方仓库不含 `containerd.io` 与 `cri-tools`，前者取自 Docker CE 阿里云源，后者取自阿里云 Kubernetes 源（路径为 `core/stable/v1.32/rpm/`，斜杠分隔，带冒号的路径返回 404）。
- kubelet 通过 CRI 只认 `k8s.io` 命名空间的镜像；`ctr` 默认落在 `default`，两者不互通。
- 镜像拉取路径由 `hosts.toml` 决定，与 `ctr` 命令行参数无关：`ctr` 不读 `config.toml`，需显式 `--hosts-dir`。

## 关键配置

**网络标识**（每台按角色改 IP 与主机名）

```
nmcli con mod <CONN> ipv4.method manual ipv4.address 192.168.80.20/24 \
  ipv4.gateway 192.168.80.2 ipv4.dns "114.114.114.114 223.5.5.5"
nmcli con up <CONN>
hostnamectl set-hostname master1
```

`/etc/hosts` 登记全部节点短名。`ip route | grep default` 与 `ip neigh show 192.168.80.2` 用于确认网关真实可达。

**内核、时钟、防火墙**

```
swapoff -a
sed -i '/swap/s/^/#/' /etc/fstab
setenforce 0
sed -i 's/^SELINUX=.*/SELINUX=permissive/' /etc/selinux/config
# /etc/modules-load.d/k8s.conf: overlay / br_netfilter
dnf install -y chrony
sed -i 's/^makestep.*/makestep 1.0 -1/' /etc/chrony.conf
systemctl enable --now chronyd
firewall-cmd --permanent --add-port=8443/tcp      # 仅 master
firewall-cmd --permanent --add-protocol=ipip
firewall-cmd --permanent --add-port=30000-32767/tcp
firewall-cmd --reload
```

`makestep 1.0 -1` 的 `-1` 表示永久允许跳变对齐，用于 VM 挂起恢复后纠正冻结的时钟。

**containerd 配置**

```
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
# 沙箱镜像：2.x 键名为 pinned_images.sandbox（单引号），不是旧的 sandbox_image
```

`/etc/containerd/certs.d/docker.io/hosts.toml`：

```
server = "https://registry-1.docker.io"

[host."https://docker.m.daocloud.io"]
  capabilities = ["pull", "resolve"]
```

**验证**（必须用原生完整地址，短名会绕过 mirror）

```
crictl pull docker.io/library/busybox:1.36
crictl images | grep busybox
ctr version; runc --version; crictl --version
```

## 验收判据

| 检查 | 预期 |
|---|---|
| `ip route \| grep default` | `via 192.168.80.2` |
| `ip neigh show 192.168.80.2` | `lladdr 00:50:56:xx:xx:xx`（VMware OUI） |
| `crictl pull docker.io/library/busybox:1.36` | 成功且 `crictl images` 显示原生完整名 |
| `ctr -n k8s.io images ls` | 与 `crictl images` 看到同一批镜像 |
| 四台互 ping | 全通 |

本阶段判据均以命令输出验收，施工期间未留截图。复现时按上表逐条核对命令返回值即可。

## 已知坑与警示

- **现象**：`ping 192.168.80.1` 通但 `ping 223.5.5.5` 全丢。
  **根因**：网关填了 `.1`，那是宿主机 VMnet8 网卡而非 NAT 设备，收到包后静默丢弃且不回 ICMP 错误。
  **判据**：`ip neigh show 192.168.80.2` 能看到 `00:50:56:xx` 才算网关正确。这是本环境隐蔽性最高的一类故障——症状在网络层，根因在配置层。

- **现象**：三条 `sed` 全部「执行成功」但配置没变。
  **根因**：containerd 2.x 键名从 `sandbox_image` 改为 `pinned_images.sandbox`；`config_path` 在文件中多处出现，只能改第一处。
  **判据**：`sed` 不报错不等于命中，改完必须 `grep` 复核。

- **现象**：`hosts.toml` 写好了，`crictl pull` 仍直连原站失败且无报错。
  **根因**：单行点号内联写法在 TOML 语法上合法，containerd 2.4 解析不出却不报错。
  **处置**：一律用 `[host."…"]` 分节 + 换行 `capabilities`。

- **现象**：`ctr images import` 成功但 `crictl images` 看不到镜像。
  **根因**：`ctr` 默认 `default` 命名空间，`crictl` 只认 `k8s.io`。
  **处置**：导出、导入、打 tag 全部带 `-n k8s.io`。

- **现象**：`kubeadm config images pull` 只拿到 6/7。
  **根因**：coredns 扁平名被源 403，中断整个流程，排在后面的 etcd 被跳过。
  **处置**：coredns 从 docker.io 拉取后 tag 成目标名；etcd 按 `images list` 输出的准确 tag 单独补拉。

- **操作纪律**：终端工具的「同步输入」会把本该单机执行的命令打到所有窗口。`join`、改配置、装包这类分角色且不幂等的操作必须先关闭同步输入。

- **Windows 侧警示**：PowerShell 5.1 读取无 BOM 的 UTF-8 中文 `.ps1` 会乱码并破坏语法；服务 / 驱动 / HKLM 类操作需管理员身份执行，普通沙箱账户调用会被拦截。
