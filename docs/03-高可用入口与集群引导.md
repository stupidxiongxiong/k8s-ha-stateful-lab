# 03 高可用入口与集群引导

> 前置：`02-主机底座与容器运行时.md`。本阶段创建集群，顺序不可调换：VIP 入口必须先于 `kubeadm init`，否则证书 SAN 里没有 VIP 地址，后续所有控制面加入都会失败。

## 架构与数据流

```
kubectl / kubelet
      │  https://192.168.80.100:8443
      v
keepalived (VRRP) ── 持有 VIP 192.168.80.100
      │  track_script chk_haproxy（探测失败 weight -60）
      v
haproxy :8443 ──roundrobin+check──> master1/2/3 :6443 (apiserver)
      │
      v
kube-apiserver ──> etcd (堆叠，本机 127.0.0.1:2379)
```

- **入口层**与**流量层**职责独立：VIP 归属由 VRRP 选举决定，后端摘除由 haproxy 健康检查决定。apiserver 被杀时 VIP 不漂移，属正确现象。
- haproxy 监听 `8443` 而 apiserver 监听 `6443`；`--control-plane-endpoint` 必须指向 VIP:8443，该地址会写入 apiserver 证书 SAN。
- Calico 以 IPIP 封装 Pod 流量；Pod 网段 `10.244.0.0/16` 与 Service 网段 `10.96.0.0/12` 都不能与节点网段 `192.168.80.0/24` 重叠。

## 关键配置

**HAProxy**（3 台 master；独立 defaults 段，不继承发行版自带的 `mode http`）

```
defaults k8s-tcp
    mode tcp
    option tcplog
    timeout connect 10s
    timeout client 4h        # 关键：继承默认的 1m 会每分钟掐断 kubectl watch
    timeout server 4h
    timeout check 10s

frontend k8s-api
    bind 0.0.0.0:8443
    mode tcp
    default_backend k8s-api-backend

backend k8s-api-backend
    mode tcp
    balance roundrobin
    server master1 192.168.80.20:6443 check
    server master2 192.168.80.21:6443 check
    server master3 192.168.80.22:6443 check
```

`haproxy -c -f /etc/haproxy/haproxy.cfg` 必须通过后才 `systemctl enable --now haproxy`。

**Keepalived**（master1 priority 200，其余 150/100；单播 peer 避免组播受限）

```
global_defs {
    router_id LVS_MASTER1
    script_user root
    enable_script_security
}
vrrp_script chk_haproxy {
    script "/usr/bin/pgrep -x haproxy"
    interval 2
    weight -60
    fall 2
    rise 2
}
vrrp_instance VI_1 {
    state MASTER
    interface ens160
    virtual_router_id 51
    priority 200
    advert_int 1
    unicast_src_ip 192.168.80.20
    unicast_peer { 192.168.80.21  192.168.80.22 }
    virtual_ipaddress { 192.168.80.100/24 dev ens160 }
    track_script { chk_haproxy }
}
```

**引导**（master1；带坑参数给全量）

```
kubeadm config images list --image-repository=k8s.m.daocloud.io --kubernetes-version=v1.32.13
kubeadm config images pull --image-repository=k8s.m.daocloud.io --kubernetes-version=v1.32.13

kubeadm init \
  --control-plane-endpoint=192.168.80.100:8443 \
  --apiserver-advertise-address=192.168.80.20 \
  --pod-network-cidr=10.244.0.0/16 \
  --image-repository=k8s.m.daocloud.io \
  --kubernetes-version=v1.32.13 \
  --upload-certs

mkdir -p $HOME/.kube
cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
chown $(id -u):$(id -g) $HOME/.kube/config
```

**Calico**（v3.29.3；manifest 里 CIDR 两行默认被注释，必须显式打开并改值）

```
sed -i -E 's|^([[:space:]]*)# - name: CALICO_IPV4POOL_CIDR|\1- name: CALICO_IPV4POOL_CIDR|' calico.yaml
sed -i -E 's|^([[:space:]]*)#   value: "192\.168\.0\.0/16"|\1  value: "10.244.0.0/16"|' calico.yaml
grep -A1 'name: CALICO_IPV4POOL_CIDR' calico.yaml
kubectl apply -f calico.yaml
```

**加入节点**（worker；控制面加入见 `04`）

```
kubeadm join 192.168.80.100:8443 --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH>
```

令牌 24h 有效，`kubeadm token create --print-join-command` 重新生成。

## 验收判据

| 检查 | 预期 |
|---|---|
| `ip -br a show ens160 \| grep 100` | 三台 master 中**有且仅有一台**持有 `192.168.80.100/24` |
| `ss -lntp \| grep ':8443'` | haproxy 在监听 |
| `kubectl -n kube-system get cm kubeadm-config -o jsonpath='{.data.ClusterConfiguration}'` | `controlPlaneEndpoint: 192.168.80.100:8443` |
| `kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}'` | `https://192.168.80.100:8443` |
| `curl -k https://10.96.0.1/healthz` | `ok` |
| 临时 Pod `nslookup kubernetes.default.svc.cluster.local` | 解析出 Service 网段地址 |

本阶段判据均以命令输出验收（VIP 归属、证书 SAN、Calico Pod 就绪），施工期间未单独留截图。复现时按上表逐条核对即可。

## 已知坑与警示

- **`--control-plane-endpoint` 端口写 6443**：证书 SAN 只会记录 init 时传入的地址，事后无法靠改 kubeconfig 补救，必须重置集群重来。端口是 8443（haproxy），不是 apiserver 的 6443。

- **`--pod-network-cidr` 用了 `192.168.0.0/16`**：会把节点网段整个包进 Pod 网段，Calico 路由与节点路由冲突。必须 `10.244.0.0/16`。

- **`haproxy -c` 报 `option forwardfor ... requires HTTP mode`**：发行版自带的 `defaults` 段是 `mode http` 并带 `option forwardfor`，被追加的 tcp 段继承。解决办法是给 K8s 单独建 `defaults k8s-tcp`，顺带修掉 `kubectl watch` 每分钟被掐断的问题。

- **keepalived 日志 `Script user 'keepalived_script' does not exist` + `SECURITY VIOLATION`**：未指定脚本执行用户与安全策略。`global_defs` 加 `script_user root` 与 `enable_script_security`；脚本本身其实一直在正常执行，属噪音型告警。

- **`grep controlPlaneEndpoint /etc/kubernetes/kubeadm-config.yaml` 报文件不存在**：kubeadm 不生成该文件，ClusterConfiguration 存在 `kube-system` 的 ConfigMap 中。这是查询路径写错，不是 init 失败。

- **coredns 长期 Pending、节点 NotReady**：无 CNI 时 kubelet 打 `network-unavailable` 污点，coredns 不容忍。装完 Calico 自动消失，属预期中间态。

- **Pod 内 `wget https` 报 `TLS error ... alert code 47`**：busybox 的 TLS 实现过于简陋，与 apiserver 握手谈不拢；集群是好的（对端已回告警）。验活改在节点上 `curl -k https://10.96.0.1/healthz`。

- **VM 重启后 `dial tcp 192.168.80.100:8443: no route to host`**：keepalived 比网卡拿到 IP 更早启动，`bind unicast_src ... failed 99` 后进入 FAULT，网卡 up 后不会自动爬回选举，三台都不持 VIP。应急 `systemctl restart keepalived`（3 台）；根治用 `NetworkManager-wait-online.service` + keepalived unit 的 `After`/`Wants` 依赖（见 `infra/bootstrap/`）。判据 `ip neigh` 从 `INCOMPLETE/FAILED` 恢复。

- **清单位置**：`infra/vip-ha/`（haproxy.cfg、keepalived.conf）、`infra/bootstrap/`（引导参数、wait-online 配置）、`k8s/network/`（Calico manifest 与 CIDR 修改说明）。
