# 08 资源治理、可观测体系与验收

> 前置：`07-故障注入、原生证据链与复盘.md`。本阶段把 `07` 的三条结论（快照不是历史、原生信号会说谎、判不了达标）变成可持续对账的指标体系，并给集群装上自动决策能力。

## 架构与数据流

两条线消费同一批「指标」，但**消费方不同，架构就不同**：

```
决策线（喂机器）
  kubelet/cAdvisor → metrics-server (metrics.k8s.io) → HPA 控制器 → 改 replicas
  驱逐请求 → PDB 预算校验 → 允许 / 拦截 evict

观测线（喂人）
  node-exporter :9100 (hostNetwork, 5 实例) ─┐
  blackbox-exporter :9115 (/probe)          ├→ Prometheus (15s 拉取, TSDB 2d)
  Prometheus 自身 localhost:9090            ┘        │
                                                     v
                                   Grafana (只读查询, NodePort 30310)
```

- **决策线**要的是「当前值 + 控制器能行动」，指标不落地也无妨；**观测线**要的是「带时间戳的历史」，靠 TSDB 存成序列才能对窗口做运算。
- `node-exporter` 用 DaemonSet + `hostNetwork: true` + `hostPID: true` + `/` 挂到 `/host`，因此 `curl 节点IP:9100/metrics` 就是 curl Pod 本身，读到的是宿主机 `/proc` 的真相。
- `headless Service`（`clusterIP: None`）属于**消费侧**：Prometheus 的 `dns_sd_configs` 靠它一次查到 5 个 Pod IP。换成普通 Service 只会出现 1 个 target。它不属于 node-exporter，换个发现方式就不需要了。
- Grafana 查 Prometheus 走集群内 DNS `http://prometheus.watch.svc.cluster.local:9090`，是 **Service ClusterIP + kube-proxy DNAT**，不是「穿透到 Pod」；Pod 内 `localhost` 是它自己，跨 Pod 不成立。浏览器入口（NodePort 30300 / 30310）对数据流零影响。

## 关键配置

**metrics-server**（v0.7.2，阿里云同步源 + 跳过自签证书校验）

```
sed -i 's|registry.k8s.io/metrics-server/metrics-server:v0.7.2|registry.cn-hangzhou.aliyuncs.com/google_containers/metrics-server:v0.7.2|' metrics-server-components-v0.7.2.yaml
sed -i 's|- --metric-resolution=15s|- --metric-resolution=15s\n        - --kubelet-insecure-tls|' metrics-server-components-v0.7.2.yaml
grep -n 'image:\|insecure' metrics-server-components-v0.7.2.yaml
kubectl apply -f metrics-server-components-v0.7.2.yaml
kubectl get apiservice v1beta1.metrics.k8s.io   # Available=True
kubectl top nodes && kubectl top pod -n gitops-lab
```

**HPA 三个前提**：副本可互换（无状态）、Pod 有 `requests.cpu`（分母）、有指标源。缺一即瞎。

```
# chart 的 deployment 模板补 resources（Burstable）
requests: { cpu: 100m, memory: 128Mi }
limits:   { cpu: 200m, memory: 256Mi }

kubectl -n argocd patch application gitops-lab --type merge \
  -p '{"spec":{"ignoreDifferences":[{"group":"apps","kind":"Deployment","name":"nginx-demo","namespace":"gitops-lab","jsonPointers":["/spec/replicas"]}]}}'

kubectl -n gitops-lab autoscale deploy nginx-demo --cpu-percent=50 --min=2 --max=6
SVCIP=$(kubectl -n gitops-lab get svc nginx-demo -o jsonpath='{.spec.clusterIP}')
ab -k -c 200 -t 120 http://$SVCIP/          # 压测打 Service，不打单 Pod
kubectl -n gitops-lab get hpa -w
```

利用率 = 单 Pod CPU ÷ `requests.cpu`，再取平均；期望副本 = `ceil(当前副本 × 平均利用率 ÷ 目标)`，再被 min/max 钳位。缩容有 5 分钟稳定窗，10% 容差带内不动作——短打（几秒）不会触发扩容，这是设计而非故障。

`ignoreDifferences` 是**必需的**：HPA 接管 `replicas` 的第一秒就与 Git 期望状态冲突，不划清字段归属，`selfHeal` 会与 HPA 反复对打。

**PDB**（`policy/v1`，保护 3 副本）

```
kubectl apply -f k8s/scaling/nginx-demo-pdb.yaml     # minAvailable: 2
kubectl -n gitops-lab get pdb                        # ALLOWED DISRUPTIONS
kubectl drain worker2 --ignore-daemonsets --delete-emptydir-data
kubectl uncordon worker2
```

`ALLOWED = max(0, healthy - minAvailable)`，按**全集群 Ready Pod** 计。PDB 是棘轮不是配额：只拦主动 evict（drain），不拦崩溃 / OOM（那归 Deployment 兜底）。`minAvailable: 3` 时 `ALLOWED=0`，drain 报 `Cannot evict pod as it would violate the pod's disruption budget`；改回 2 后驱逐才逐个放行，`get pdb -w` 能看到 `ALLOWED` 随 Pod 重建呈方波。**只允许 drain worker2**——worker1 上有 MySQL 的 local-path PV（见 `05`）。

**观测栈清单**（全部落档，不用 here-doc，见 `k8s/monitoring/`）

| 对象 | 关键点 |
|---|---|
| `namespace-watch.yaml` | 命名空间 `watch` |
| `node-exporter-daemonset.yaml` | `--path.rootfs=/host`；tolerations `Exists` 让 master 也跑 → 5/5 |
| `blackbox-exporter.yaml` | ConfigMap `web.yml` 定义模块 `http_2xx: prober: http`；blackbox **没有默认模块**，此配置是必需项 |
| `node-exporter-headless-svc.yaml` | `clusterIP: None`，供 `dns_sd_configs` 发现 5 实例 |
| `prometheus.yaml` | 3 个 job：自身 `localhost:9090`、node-exporter DNS SRV/A 记录、blackbox `/probe?target=...`；`scrape_interval: 15s`；TSDB `2d` + `emptyDir` |
| `grafana.yaml` | 数据源 URL 为集群内 Service DNS；管理员密码用占位符或 Secret 注入 |

**PromQL 对账**（在 Prometheus 自带 `/graph` 或 Grafana Explore 跑；两者查同一份 TSDB）

```
avg_over_time(probe_success[30m])          # 30 分钟窗口成功率，判据 ≈ 1
1 - avg_over_time(probe_success[30m])      # 错误预算消耗，判据 ≈ 0
probe_duration_seconds                     # 探测耗时，判据 0.01s 量级
probe_http_duration_seconds                # 分阶段耗时：resolve/connect/tls/processing/transfer
```

`probe_success` 的 0/1 是**判定结果**不是算法，旁边还有 `probe_http_status_code`、`probe_duration_seconds` 等原始量；判定标准本身也能换（`http_2xx` → `tcp_connect` / `dns` / `icmp`、加 `fail_if_body_matches_regexp`）。node-exporter 则相反：一批 collector 默认开、一批默认关，裸装时 `--path.rootfs=/host` 一个 collector 参数都没写，吃的是默认集全量；裁剪不归 exporter 管，是 Prometheus 侧 `metric_relabel_configs` 的事。

「CPU 使用率」是查询侧口径产物，采集侧只吐 `node_cpu_seconds_total` 各类 mode 的累计秒数。`100 - avg by(instance)(irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100` 只是最简口径；换 `rate`、换 `[1m]`、换 `sum by(instance)`、改用 cAdvisor 序列、排除 `steal`，结果都不同。口径要写进 SLO 文档与人对齐，比公式本身重要。

## 已知坑与警示

- **开机连环三案**：① 新节点 kubelet 未自启 → `NodeNotReady`（Conditions 里 `Kubelet stopped posting node status`）；② argocd 的 redis / dex `ImagePullBackOff`，真凶是 `imagePullPolicy: Always` 在离线环境强制联网报到，**不是镜像不存在**，改用 `--type json` patch 成 `IfNotPresent`（`--type merge` 打数组会报 `image: Required value`）；③ 新节点没有存量镜像，需从已有节点 `ctr -n k8s.io images export/import` 补发。这三条叠加时「镜像在不在」的结论会反转，必须先确认本地镜像与拉取策略。

- **`resources` 加到了教学 chart 目录**：`/root/soft/demo-chart` 不是 GitOps 那份。用 `git diff \| grep -vE '^[+-]\s*#'` 滤掉注释行看实质差异，判据是只多出 resources 那几行。

- **压测太短不触发扩容**：`ab` 打 5 秒看不到任何变化，需 120 秒以上高并发；缩容还要再等 5 分钟稳定窗。这是 HPA 的三延迟，不是故障。

- **把 PDB 当配额 / 以为它防崩溃**：PDB 只管自愿中断，且按全集群 healthy 算余额。`ALLOWED` 是瞬态值，边驱逐边 Ready 时呈方波。

- **`drain worker1`**：MySQL 的 local-path PV 钉在该节点，两个副本同时腾挪且新节点无本地数据。只允许 drain worker2，收尾必须 `uncordon`。

- **Grafana 密码写进 yaml 后直接 git**：占位符方案下直接 apply 会把字面量 `<占位符>` 当密码；Secret 方案下清单里只有名字、真值在 etcd。三种位置要分开看：工程目录清单（入 Git）、VM 运行时副本（不入 Git）、etcd 里的对象（apply 时写入）。**Git 历史是追加的**，真值一旦 commit 过，改最新版没用。Secret 的 base64 只是编码不是加密，生成 `secret.yaml` 再提交等于没脱敏。

- **`apply` 之后改文件不影响集群**：真值已经进 etcd，`kubectl get deploy -o yaml` 能看到；改 Secret 后已运行的 Pod 不会热更新，要重建。

- **把 headless Service 塞进 node-exporter 的 yaml**：它没有顺序依赖（selector 只认 label），但归属是消费侧；`kubectl delete -f` 一个多文档文件会把 Service 一起删掉。

- **探测耗时的大头是 `resolve`**：target 写的是 Service DNS 名而非 IP，每次探测都要问 CoreDNS；Go 程序默认不做应用层 DNS 缓存。约 8 成时间花在这里属正常且故意——每次重新解析才能跟上 Pod IP 变化，别去「优化」它。真正该警觉的是红线基线整体抬升（CoreDNS 压力），不是孤立尖峰。

- **拿 `probe_duration_seconds` 判断慢在哪**：它包含 DNS、建连、TLS、收发、读 body 与模块判定。要看分阶段得查 `probe_http_duration_seconds{phase="..."}`；`probe_success` 与耗时是**同一次探测、同一组输出**，时间戳严格对齐。

- **清单位置**：`k8s/scaling/`（metrics-server、resources patch、HPA、PDB）、`k8s/monitoring/`（6 份清单 + 大盘 JSON + PromQL）、`assets/architecture/`、`assets/screenshots/`。
