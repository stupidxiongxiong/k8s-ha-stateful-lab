04infra/ — 主机底座

装 K8s 之前、作用在每台节点上的配置。这里的参数写错，集群装不起来或埋下隐蔽故障。

infra/vip-ha/高可用入口

haproxy 提供统一 TCP 入口 :8443，keepalived 让这个入口的 VIP 192.168.80.100 在三台 master 间漂移。两个独立程序各管一半：keepalived 管地址漂移（三层），haproxy 管后端转发与摘除（四层）。

文件作用
haproxy.cfg追加段：defaults k8s-tcp（避免继承 1 分钟超时掐断 watch）+ bind 0.0.0.0:8443 + 三台 apiserver 的 roundrobin 后端。三台 master 内容一致。
keepalived-master1.conf主配置：priority 200、state MASTER、weight -60（须大于优先级间隔 50，否则 haproxy 死了 VIP 也不漂）。
keepalived-master2.conf备：由 master1 改 5 处（router_id / state / priority 150 / src_ip / peer），VRID 保持 51。
keepalived-master3.conf备：同上，priority 100。

infra/containerd/容器运行时

原生 containerd（无 docker），负责拉镜像与跑容器。Rocky 官方仓库不提供 containerd/cri-tools，来源是 Docker CE 源与 K8s 源。

文件作用
config-toml-changes.md记录 config.toml 的三处必改（cgroup=systemd、沙箱镜像换源、镜像加速目录）。该文件是 containerd config default 生成的产物，不入库。
hosts-docker-io.tomldocker.io 走 daocloud mirror。必须用 [host."..."] 分节写法；点号内联写法 containerd 2.4 读不出且静默直连原站。
hosts-quay-io.tomlquay.io 备用 mirror。本项目 Calico 走 docker.io，此份留作备用。

infra/bootstrap/集群引导

内核与时间的前置条件，以及 kubeadm init 的权威参数。

文件作用
modules-k8s.conf/etc/modules-load.d/k8s.conf：overlay + br_netfilter，让网桥流量进 iptables。
sysctl-k8s.conf/etc/sysctl.d/k8s.conf：三个 bridge-nf-call 与 ip_forward=1，三者缺一则 Calico/kube-proxy 不成立。
chrony.md时间同步改动：makestep 1.0 -1 允许 VM 挂起后强制对齐，否则证书校验与 etcd 时序判据失真。
kubeadm-init.mdinit 参数与硬约束：endpoint 必须 :8443（写进证书 SAN 改不了），Pod CIDR 必须 10.244.0.0/16（不能压节点网段）。

08约定

  • 单向派生：本仓是复现参考，由施工版单向派生；不回写施工版，两处不双向编辑。
  • 去时间叙事：文档按 01–08 顺序编号，不出现 Day/任务号、第一人称与主观叙事；踩坑写成"已知坑与警示"。
  • 凭据不入库：密码/PAT/私钥一律占位符，真值只在 VM 上注入。已全仓扫描确认无真私钥、无明文密码。
  • 不囤上游产物：Calico manifest、containerd 生成的 config.toml、离线镜像包都不入仓，只留来源与改动说明。
  • 证据可追溯：docs 的判据 → 同名证据图 → 原始留档，三者一一对应。
